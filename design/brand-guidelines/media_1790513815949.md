## 1. What changed, and why this is a rewrite

The previous spec described a three-day, multi-track, ticketed conference with a hackathon alongside it. The 2026 concept is a different event. Carrying over the old IA would produce a site that misrepresents the product.

| | Previous spec (2025 model) | **AIX Summit 2026** |
|---|---|---|
| Duration | 3 days (24–26 Oct 2025) | **One day — Monday 14 December 2026** |
| Hours | Multi-day | **10:00–16:30**, reception to **18:00** |
| Venue | QSTP, Education City | **Marriott Marquis City Center Doha** *(subject to confirmation)* |
| Hackathon | Sister programme, referenced | **Removed entirely. No hackathon component.** |
| Scale | Mass-market conference | **75 roundtable seats; ~110 people on site** |
| Hero content | Speakers + agenda | **Five sponsored executive roundtables** |
| Registration | Ticket sales, pass tiers | **Invitation-led. "Request an invitation." No public ticket sales in 2026.** |
| Content structure | Tracks, filterable agenda, session directory | **One programme. Five roundtables. Small speaker roster.** |
| Post-event asset | — | **AIX Roundtable Signals** report, published mid-January 2027 |
| Commercial flagship | Sponsorship tiers | **Roundtable Chair** — the flagship product after Strategic Partner |

**Deletions from the old spec — remove, do not repurpose:**
- `/agenda` with day tabs, track filters, format filters, room filters, URL-synced query state, session detail routes. A one-day, single-block programme does not need a filtering system; it needs one well-designed page.
- `/tracks` and `/tracks/[slug]`. Roundtables replace tracks.
- `/attend` pass-comparison tables, pricing, `soldOut` / group-registration logic. There is no ticketing.
- `/register` multi-step checkout. Replaced by an application form.
- `/showcase` as a startup-pitch exhibitor list. The Showcase is demonstrations, explicitly **not** a competition.
- All hackathon references, including the "sister programme" card and the `features.showHackathonReference` flag.
- **The 2025 hackathon proof points** (80+ teams, 12 finalists, $20,000 prize pool). The old spec used these as social proof. They now advertise a product that no longer exists and pull directly against "no hackathon in the primary Summit proposition." Use the 2026 model's own numbers instead (Section 7.1, S3).

**One more deletion, flagged explicitly because it is a reputational risk:** the concept document states that AIX is independent of **World Summit AI MENA** and that it must not be presented as a partner, affiliate, or related event. Do not list it under partners, do not mention it in copy, do not reference it in metadata or schema. If date context is ever needed it appears as a separate event only, with no relationship implied.

## 2. The internal/public boundary — read before building

The concept document is an **internal working document**. Most of it must not appear on the public site. Treat the table below as a build rule.

### 2.1 Never publish

| Internal content | Why it stays internal |
|---|---|
| Delivery team, owners, roles (§19) | Internal staffing |
| Critical path and milestone dates (§20) | Internal deadlines |
| Risk register (§18) | Discloses operational vulnerabilities |
| Success measures and targets (§17) | Commercial targets |
| Sponsorship pricing, benefit economics (§10) | Gated; prospectus only |
| Capacity arithmetic — the 90-confirmed-to-seat-62 ratio, waitlist mechanics, drop-out assumptions (§3) | Reveals that invitations are over-issued |
| Roundtable **options matrix** (§11) — alternatives, reserves, sponsor-potential ratings | Names organisations not approached, and rates them |
| Detailed **seat plans** by named organisation type (§6) | Contains competitive sensitivities — e.g. the CBQ competitor-bank condition |
| Chair **alternatives** and fallback tables | Signals that chairs are unconfirmed |
| "Subject to confirmation" venue status shown as uncertainty | See 2.3 |
| Recognition go/no-go threshold (§9) | Reveals the award may not run |
| Moderator/rapporteur contracting, briefing schedule (§7) | Internal ops |

### 2.2 The confirmation gate

Chair organisations in the concept document — **CBQ, QatarEnergy, NCSA, MCIT, Ooredoo** — are explicitly described as *"targets / working assumptions until confirmed through outreach."* Chairs are not due to be confirmed until **31 October**, and the site goes live **9 November**.

Publishing "powered by CBQ" before CBQ has signed would be a commercial and legal problem. So the gate is enforced in code, not left to editorial discipline:

```ts
type PublishStatus = 'confirmed' | 'pending' | 'target';

type Roundtable = {
  slug: string;
  title: string;              // always public — e.g. "The AI-Powered Financial Institution"
  shortTitle: string;         // "FinTech & Financial Services"
  coreQuestion: string;       // always public
  lane: string;               // always public
  themes: string[];           // always public
  participantProfile: string[]; // public, generalised — NOT the internal seat plan
  chair?: {
    status: PublishStatus;
    organisation?: string;    // rendered ONLY when status === 'confirmed'
    logo?: string;
    personName?: string;
    personRole?: string;
  };
  order: number;
};
```

**Build-time guard.** Add a validation step to the build that fails on any of these:
- a `chair.organisation`, `chair.personName`, `partner.name`, `speaker.name`, or `showcaseCompany.name` present on a record whose `status !== 'confirmed'`
- a `venue.name` rendered publicly while `venue.status !== 'confirmed'`
- any string from a maintained `content/_internal-denylist.json` (populate it with: "options matrix", "first reserve", "go / no-go", "World Summit AI MENA", "waitlist", chair-alternative organisation names) appearing anywhere in rendered output

Run it in CI and as a pre-deploy check. A failing guard blocks deployment. This is cheap to build and it removes an entire class of expensive mistake.

**Rendering unconfirmed records.** A roundtable with an unconfirmed chair still gets a full, confident page. The topic, the question, the lane, the themes and the participant profile are all publishable and are the substance anyway. Only the chair slot changes:

> **Chair:** To be announced

Never "TBC", never an empty logo box, never a greyed placeholder that reads as a gap. The page must not look unfinished — it must look like an event whose line-up is being announced in sequence. Add a one-line "Chairs announced as they are confirmed" note plus an email capture on `/roundtables`, which converts the gap into a list-building opportunity.

### 2.3 Venue

The venue is a working assumption pending contract signature (due 31 October). Until `venue.status === 'confirmed'`, render location as **"Doha, Qatar"** everywhere — hero, metadata, schema, footer. Do not name the hotel, and do not write "venue TBC", which reads as disorganisation. Once confirmed, flipping one field in `site.json` fills in the venue name, address, map and travel content site-wide. Build `/venue` so it degrades to a Doha-level travel guide without the hotel specifics.

## 4. Objectives

The commercial model rests on sponsorship, and the guest list is the product being sold. So the site has two audiences with different jobs to do.

| Priority | Audience | Conversion | Primary route |
|---|---|---|---|
| 1 | Prospective **sponsors** — specifically Roundtable Chairs | Prospectus download, partnership enquiry | `/partners/become-a-partner` |
| 2 | Prospective **guests** | Invitation request | `/request-an-invitation` |
| 3 | Invited guests | Confirmation, credibility check before accepting | `/roundtables`, `/programme` |
| 4 | Showcase applicants | Application | `/showcase/apply` |
| 5 | Media | Press kit, accreditation | `/media/press-kit` |

**A design consequence worth stating plainly.** The sponsorship pitch is "a topic, a room, 12 senior guests and a thought-leadership outcome." A sponsor evaluating that will land on `/roundtables/[slug]`, not the homepage. Those five pages carry the commercial weight of the site and should get the most design effort — not the hero. Every roundtable page needs a visible "Chair this roundtable" path alongside the guest-facing content.

**A tone consequence.** This is a 110-person invitation-led executive event. Copy that shouts — countdown timers, "limited seats remaining", exclamation marks, "don't miss out" — actively damages it. Scarcity is real here and does not need selling. Write with restraint, in the register of an institutional invitation.

## 5. PHASE 0 — Theme extraction (do this first)

Brand continuity is a requirement: same logo, same palette, same typography, same visual language as aixsummithack.com. But **that site renders entirely client-side** — the served HTML is an empty shell and all styling is injected by JavaScript. Its design system cannot be read from source. Extract it from the running page.

### 5.1 Procedure

1. Open `https://www.aixsummithack.com/` in a headless browser with JavaScript enabled. Wait for network idle.
2. Full-page screenshots at **1920, 1440, 1024, 768, 390** → `design/reference/`.
3. Extract the computed design system:
   ```js
   const els = [...document.querySelectorAll('*')];
   const freq = (fn) => {
     const m = new Map();
     els.forEach(el => { const v = fn(getComputedStyle(el)); if (v) m.set(v, (m.get(v)||0)+1); });
     return [...m.entries()].sort((a,b) => b[1]-a[1]).slice(0, 40);
   };
   copy(JSON.stringify({
     colors:      freq(s => s.color),
     backgrounds: freq(s => s.backgroundColor),
     gradients:   freq(s => s.backgroundImage !== 'none' ? s.backgroundImage : null),
     fonts:       freq(s => s.fontFamily),
     weights:     freq(s => s.fontWeight),
     sizes:       freq(s => s.fontSize),
     lineHeights: freq(s => s.lineHeight),
     letterSpace: freq(s => s.letterSpacing),
     radii:       freq(s => s.borderRadius),
     shadows:     freq(s => s.boxShadow !== 'none' ? s.boxShadow : null),
     borders:     freq(s => s.borderColor),
     transitions: freq(s => s.transition !== 'all 0s ease 0s' ? s.transition : null),
   }, null, 2));
   ```
4. Dump `:root` custom properties:
   ```js
   const r = getComputedStyle(document.documentElement);
   Object.fromEntries([...r].filter(p => p.startsWith('--')).map(p => [p, r.getPropertyValue(p).trim()]));
   ```
5. Download brand assets: every `<img>`/inline `<svg>` matching `logo|mark|brand|aix`, `link[rel*=icon]`, and every `.woff2`/`.woff` in the Network panel → `public/brand/`, `public/fonts/`.
6. Record the hero background treatment precisely — solid, gradient, mesh, image, video, canvas/particle, noise overlay — including gradient direction and colour stops.
7. Record button and nav-link hover/focus states: transform, colour and shadow deltas.
8. Record scroll-reveal behaviour: fade, translate, stagger, duration, easing.

### 5.2 Output contract — `design/tokens.json`

Fallbacks apply **only** where extraction fails for that specific token. Log every fallback used in `design/EXTRACTION-NOTES.md` so the client can correct it.

| Token | Source | Fallback |
|---|---|---|
| `color.bg.base` | Most frequent page background | `#070710` |
| `color.bg.raised` | Card background | `#0F0F1C` |
| `color.bg.overlay` | Modal scrim | `rgba(7,7,16,0.72)` |
| `color.text.primary` | Body copy | `#F4F4F8` |
| `color.text.secondary` | Muted copy | `#A0A0B4` |
| `color.brand.primary` | Primary button fill | *extract — never guess* |
| `color.brand.secondary` | Accent / link | *extract — never guess* |
| `color.border.subtle` | Card border | `rgba(255,255,255,0.08)` |
| `gradient.hero` | Hero background-image | *extract — never guess* |
| `font.display` | `h1`–`h3` family | *extract, self-host* |
| `font.body` | `p` family | *extract, self-host* |
| `radius.sm/md/lg/pill` | Button/card/badge radii | `6 / 12 / 20 / 999px` |
| `shadow.card` / `shadow.raised` | Card shadows | `0 1px 2px rgba(0,0,0,.4)` / `0 12px 32px rgba(0,0,0,.45)` |
| `motion.duration.fast/base/slow` | Transition durations | `150 / 250 / 400ms` |
| `motion.ease.standard` | Easing | `cubic-bezier(.22,1,.36,1)` |

**Plus five roundtable accents.** Each of the five roundtables needs a distinguishing accent, derived as tints/shades of the extracted brand colours — never invented hues. Each must reach **4.5:1** against both `bg.base` and `bg.raised` when used for text; if it cannot, restrict it to borders and badge fills with `text.primary` on top.

**Hard rule:** no hex value, font stack, radius, shadow or duration anywhere outside `tokens.json`. `grep -rE '#[0-9a-fA-F]{6}' src/` must return nothing.

### 5.3 Logo

Prefer SVG; request the vector from the client if only raster exists. Build `<Logo variant="full|mark" theme="light|dark|mono" size />`. Never redraw, recolour, stretch, rotate or add effects. Clear space equal to the mark's cap-height on all sides. Favicons: `favicon.ico` (32), `icon.svg`, `apple-touch-icon.png` (180), `icon-192.png`, `icon-512.png`, `manifest.webmanifest`.

Note the wordmark change: the 2025 site reads "AIX Summit | AIX Hackathon 2025". The new site is **AIX Summit 2026**. If the extracted logo contains hackathon lockup elements, use the Summit-only variant and flag it for the client.

### 5.4 Dark / light mode

Match the reference site's single mode exactly. No theme toggle unless asked. Define tokens under `:root` so a second mode is later config, not a refactor.

## 10. Technical stack

**Required**
- **Next.js (App Router)**, TypeScript strict
- **SSG by default**, ISR (`revalidate: 300`) for content that will change during the announcement run-up. Server components except interactive islands. No page may depend on client-side JS to render primary content — this is the reference site's core failure and fixing it is the largest single improvement available.
- **Tailwind CSS**, theme generated from `design/tokens.json` — one source, not two
- **next/font**, self-hosted woff2, `display: swap`, display face preloaded
- **next/image** for raster; inline SVG for icons and logos
- **Zod** schemas shared client/server
- **MDX** for `/media`, `/signals` editions and legal pages

**Recommended** — Radix or Headless UI for accordion, select, dialog (correct a11y for free); CSS transitions over `framer-motion` unless the reference motion demands it; Vercel hosting; Plausible or Vercel Analytics.

**Not permitted** — client-only rendering of page content; design values outside `tokens.json`; third-party iframes before interaction; `localStorage` for anything beyond non-essential UI preference; unlabelled inputs; `div` buttons; `outline: none` without a replacement; **any rendering path that can output an unconfirmed organisation name**.

## 14. Accessibility

WCAG 2.1 AA.

- Contrast ≥ 4.5:1 body, ≥ 3:1 large text and UI boundaries. Verify all five roundtable accents against both backgrounds (§5.2).
- Full keyboard operability, logical tab order, visible focus everywhere.

- Focus trapped in mobile nav, mega-menu and modals; returned to trigger on close.

## 16. Copy principles

The register is the hardest thing to get right on this site, and it is easy to break.

**Write like this** — restrained, specific, confident. "Five parallel conversations, 105 minutes, fifteen seats each." "AIX Summit 2026 is invitation-led." "Not a pitch competition."

**Never** — countdown timers, "limited seats remaining!", "don't miss out", "secure your spot", exclamation marks, "revolutionary", "game-changing", "unlock", "supercharge", "cutting-edge", vendor-brochure adjectives, or any phrasing that implies tickets are for sale.

**Specifics beat superlatives.** "Twelve invited guests at each table" carries more weight than "exclusive access to industry leaders." The concept document's own numbers are the best copy the site has.

**British English**, consistently — "organisation", "programme", "recognise", "centre". The concept document uses it throughout.

**Use "roundtable"** (one word, lowercase unless in a title). **"AIX Roundtable Signals"** and **"AIX AI Impact Recognition"** are proper nouns — capitalise exactly. "Enterprise Connections" capitalised. "AI Showcase" capitalised.
